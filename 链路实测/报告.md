## ③ 视频（test_video_comfyui.py）

- 输入 = ②的真实 TTS 截 5s（PCM16）+ 人像图，走 `本地引擎工作流/infinitetalk-数字人_api_windows兼容.json`（25 节点）。
- **主包实例（Python 3.13 venv）：2/2 必崩**。每次在 14B 采样第 0 步（`Generated new RoPE frequencies` 后）进程段错误退出（exit 139，无 Python 异常），崩前显存 15.8/16.3GB。系统 RAM 32GB/页面文件均充裕，排除内存不足；节点与 6 个模型文件（含 16.4GB fp8 主模型）、wav2vec 缓存都在。定性：**主包 torch/kernels 环境对 fp8_scaled 14B 推理的原生层故障**。
- **Runtime 实例（`D:\PPT_Studio_Assets\InfiniteTalk_TTS\InfiniteTalk_Runtime`，PPT 数字人同款栈）：一次通过**。5s 音频 → 2 个 81 帧窗口 × 4 steps（约 65s/step）→ VAE 解码 → 520s 出片，显存峰值仅 7.6GB（block-swap 38 层）。
- 集成注意点：
  1. DuoCast 视频适配器必须**对接 Runtime 实例**（或先修主包环境），启动方式与 PPT `start_digital_human_stack.ps1` 相同，与主包 8188 互斥。
  2. 工作流原引用的哈希 png/mp3 输入已不存在 → 适配器需自行供图/供音（本次 TTS→视频串联已验证）。
  3. 时长由音频自动推导（frames = 秒×25+1），成片节奏 ≈ **104× 实时**（5s 片 8.7min）。整期 5 分钟播客 ≈ 8.7 小时 → **真实生产必须做镜头分段并行/优化，或只渲染口播窗口**，这是容量规划级发现。

## 修复落地（goal #2，同日追加）

### 视频 block-swap A/B（Runtime 实例，5s 音频 2×81 帧窗口，非生产参数唯一变量）

| 配置 | 结果 | 用时 | 备注 |
|---|---|---|---|
| swap=38, non_blocking=false（基线） | ✅ | 520s | 显存峰值 7.6GB |
| swap=32, non_blocking=false | ✅ | 450s | **采纳**：-13%，余量仍足 |
| swap=28, non_blocking=false | ✅ | 460s | 与 32 差异在噪声内，显存占用更高 |
| swap=24, non_blocking=true | ❌ CUDA OOM | — | step 0 即爆 |
| swap=16, non_blocking=true | ❌ 病态颠簸 | >20min 未完成 step0 | GPU 100%/80W，WDDM 共享内存回退 |

- 结论：16GB 卡安全提速点在 **swap≈32**（估算峰值 ~10GB）；再低收益趋零并迅速越过 OOM 悬崖。
- 已固化：`本地引擎工作流/infinitetalk-数字人_api_windows兼容.json` node134 `blocks_to_swap: 38→32`（use_non_blocking 保持 false）。
- 产物：`_video/swap28_00001-audio.mp4`、`_video/swap32_00001-audio.mp4`（与基线同尺寸 302KB/时长字段一致）。
