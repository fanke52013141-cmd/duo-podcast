# 双声播客工坊 DuoCast

面向 **Windows 本地部署**的双人播客视频自动化生产工作台方案文档。

一句话：从「一个话题或一篇文章」出发，产出「一段 ≤10 分钟的双人对谈视频」，全程数据不出本机。

## 方案核心

### 生产链路（八步）

```
P1 角色库 ──▶ P2 内容输入 ──▶ P3 分角脚本 ──▶ P4 配音锁轨
                                                    │
                                                    ▼
P8 渲染与导出 ◀── P7 试镜 ◀── P6 镜头表 ◀── P5 视觉设定
```

| 步骤 | 产出 | 关键点 |
|---|---|---|
| P1 角色库 | 形象图 + 参考音 + 角色设定图 | A 主持人固定跨期复用；B 嘉宾每期可变 |
| P2 内容输入 | 播客稿 | 话题 / 文章 → LLM 生成，可流式编辑 |
| P3 分角脚本 | `lines[]`（逐句说话人 + 语气 + 语速） | 自动分角 + 逐句可改 |
| P4 配音锁轨 | **时间轨**（唯一坐标系） | 按说话人整段合成 + ASR 回填句级时间码 |
| P5 视觉设定 | **同框底图**（唯一首帧）+ mask | 图生图融合，不是贴图 |
| P6 镜头表 | `shots[]` + ffmpeg 滤镜链 | 切镜 + 数字运镜，**不做摇镜** |
| P7 试镜 | 5 秒样片 + 四项验收 | 通过后才投入长片渲染 |
| P8 渲染与导出 | 成片 | 分段串行渲染、可续跑、拼接、补帧 |

### 与旧方案（v1.0）的关键差异

| 维度 | v1.0 | v2.0 |
|---|---|---|
| 时间轨来源 | 前端按 4.2 字/秒**估算** | **TTS 实际输出 + ASR 回填** |
| 底图生成 | 角色图 + 场景图 → **贴图合成** | **图生图融合**（模型重新生成「两人已在场景中」的图） |
| 遮罩 | 手动笔刷涂抹 | 自动生成（左右站位 + bbox 校正） |
| 说话人绑定 | 遮罩 + 双轨 | **`add` 模式零音频填充** + mask 跨注意力分配 |
| 镜头语言 | 分镜 | 切镜 + 数字运镜（推/拉/裁切），**不做摇镜** |
| 语音合成 | 逐句 | **按说话人整段合成** |
| 工作模式 | 单一手动 | **手动可调 → 确认关卡 → 一键生成** |

### 三个核心机制

**① 每步可调** — 每个步骤可独立重跑、局部重跑（单句重录 / 单段重渲染）、参数全暴露、版本可回退，并有完整的**依赖失效传播**（改了上游，下游自动标「已过期」）。

**② 确认关卡** — 6 个人眼判断点做成显式暂停面板，每个可配置为「必须确认 / 自动通过 / 跳过」：

| 关卡 | 内容 | 执行顺序 |
|---|---|---|
| CP-1 | 角色确认 | 1 |
| CP-2 | 稿件确认 | 2 |
| CP-3 | 底图确认 | 3 |
| CP-4 | 配音确认 | 4 |
| CP-5 | 镜头确认 | 5 |
| CP-6 | 试镜确认 | 6 |

> 编号按「确认内容」分组并固定不变，避免与工程文件、日志中的引用冲突。

**③ 一键生成** — 前提是各环节已手动打磨通畅。输入话题或文章即可自动跑完全流程，仅在勾选的关卡处暂停；产物与手动模式完全一致，**可事后回到任意一步微调并局部重跑**。

## 技术选型（摘要）

| 层 | 选型 |
|---|---|
| 前端 | React 18 + TypeScript + Vite + Tailwind CSS + Zustand + TanStack Query |
| 可视化 | WaveSurfer.js（时间轨）、Konva（站位框 / mask 精修）、dnd-kit（排序） |
| 后端 | Python 3.11 + FastAPI + WebSocket + arq（任务队列） |
| 推理编排 | ComfyUI（`127.0.0.1:8188`） |
| 后处理 | ffmpeg（拼接 / 运镜 / 音画合并）+ RIFE（补帧） |
| ASR 对齐 | faster-whisper large-v3 |
| 数据存储 | 无数据库，工程 = 一个文件夹 + `project.json` |

| 用途 | 首选 | 备选 |
|---|---|---|
| TTS / 音色克隆 | **IndexTTS-2.5** | Fun-CosyVoice3-0.5B |
| 形象 / 场景 / 底图融合 | **Qwen-Image-Edit 系列** | FLUX Kontext 系列 |
| 口型视频 | **InfiniteTalk-MultiTalk** | LongCat-Video-Avatar 1.5 |
| 补帧 | **RIFE** | — |

## 两条必须记住的技术约束

> 以下事实已核对 InfiniteTalk 官方仓库源码与 IndexTTS 官方 README。

1. **InfiniteTalk 多人物模式下，默认 mask 是画面左右各半。** 未提供 bbox 时模型硬切左右半幅，因此底图必须让**两人左右分居、居中留空**。若两人前后错开或偏中，必须用 bbox 校正。
2. **IndexTTS-2.5 的 `use_random` 必须保持 `false`。** 官方明确说明开启随机采样会降低音色克隆保真度。情绪向量为 **8 维**，顺序固定：`[happy, angry, sad, afraid, disgusted, melancholic, surprised, calm]`。

补充：官方说明 InfiniteTalk 的 I2V 模式**超过 1 分钟会出现明显颜色漂移**，需分段渲染 + 固定首帧。

## 已知风险（开工前必读）

| # | 风险 | 影响 | 验证时机 |
|---|---|---|---|
| **R1** | InfiniteTalk 480p 在 **16 GB 显存**上跑不起来或极慢 | 整个视频侧不成立 | **第 1 周** |
| **R2** | RTX 5080（Blackwell sm_120）与 flash-attn / CUDA 扩展不兼容 | 环境搭不起来 | **第 1 周** |
| R3 | 镜头切换导致身份 / 背景漂移 | 成片不可用 | 第 2 周 |
| R4 | 长片颜色漂移（官方已知） | 后半段偏色 | 第 3 周 |
| R5 | 图生图融合出的底图两人站位不对 | mask 错位、口型串位 | 第 2 周 |

> **决策点**：先做 **30–60 秒 pilot**（一张同框底图 + 两条交替音轨 + `add` 模式，不切镜、不特写、不补帧），同时实测渲染倍率 R。R1 或 R2 不通过，需重新评估视频侧模型或降低目标。

## 开发路线图

| 阶段 | 周期 | 内容 |
|---|---|---|
| 0 · 技术验证 | 1 周 | 环境搭建、**pilot 渲染**、**吞吐实测**、图生图融合验证 |
| 1 · 骨架与角色库 | 1.5 周 | 前端骨架、后端骨架、P1 角色库、工程持久化 |
| 2 · 内容与音频 | 1.5 周 | P2 内容输入、P3 分角脚本、P4 配音锁轨、时间轨组件 |
| 3 · 视觉与镜头 | 1.5 周 | P5 视觉设定、P6 镜头表、时间轨集成 |
| 4 · 渲染与成片 | 2 周 | P7 试镜、P8 渲染队列、后处理、导出 |
| 5 · 一键生成与打磨 | 1.5 周 | 确认关卡、P9 一键生成、依赖失效、打磨 |

**总计约 9 周**（单人全职，不含等待模型下载）。

## 明确不做（本期边界）

- ❌ 真实摇镜 / 复杂运镜 / 多机位切换
- ❌ 云端推理、多用户、账号体系
- ❌ 实时预览
- ❌ 移动端完整支持
- ❌ 字幕 / 多语言配音 / 后期特效
