# 两轮预览与局部重生成实施设计

状态：核心流程已接通代码并完成无模型验证，正式部署和新路径真实验收待执行。2026-10-28最新进展见EXPERT_CONTINUATION_20261028.md；本文不能作为功能已上线的证明。

## 用户流程

配音与角色素材就绪后，默认提供“生成两轮预览”：A问→B答→A问→B答，四个话轮；不足四轮时使用现有完整话轮。默认开头两轮，也允许选取连续两轮，便于检查复杂句或不同机位。只生成选定内容及必要上下文，不先算整期。

预览使用最终模型、分辨率、ROI、声音、采样步数与拼接规则。展示实际预计范围，不以降质预览代表最终质量。用户可逐轮播放、看整段交接，并选择“采用预览继续整期”或“调整本轮”。通过预览仅说明这些内容通过，不能替代整片验收。

已通过预览的模型窗口在输入及依赖相同、文件核验通过时复用到正式整期。预览从冻结的整期计划中选择窗口，保留原绝对时间、原始上下文和随机种子，不能另切成零起点小工程后期望直接复用。

每轮问答提供“重新生成画面”“修改配音／文本”“查看候选”“采用此版”“恢复旧版”。新候选成功并通过检查前，当前采用版持续可用。操作不自动覆盖旧正式成片。

## 数据与依赖

- `turnId`为稳定话轮ID；一轮问答保存两个turnId，不用列表下标当身份。文本和配音候选分别保留版本。
- `episodeSnapshotId`冻结脚本、音频时间轨、动作包、机位、渲染规格及运行时身份。预览和整期绑定同一快照。
- `windowId`对应模型窗口，保存核心帧/样本区间、上下文区间、原始任务ID、依赖摘要、媒体SHA、实际帧数及检查状态。
- `turnWindowBindings`保存话轮与窗口的多对多关系。一个话轮可能跨多窗；一窗也可能含角色交接，不能认定一轮等于一次模型调用。
- `candidateId`独立于依赖摘要，允许相同输入主动重试。依赖用于判定可复用性，候选ID用于区分生成版本。主动“再来一版”只改变选定窗口的采样种子／变体ID，不能重置整期种子导致全部失效。
- `assemblyVersion`保存当前采用窗口映射。采用候选后原子更新，重新拼接音轨与整片；保留旧版本可回退。

当前专家规划器的seed由完整segment摘要产生，其中有绝对帧/样本等信息；不能直接声称改词后下游仍可复用。需要将局部内容依赖、候选采样身份、整期放置时间分开，同时保持源动作/音频上下文的真实依赖。

## 失效规则

| 操作 | 模型需要重新生成 | 后处理 |
|---|---|---|
| 画面不满意，文本/声音/时长不变 | 选中话轮相交窗口；先保证边界上下文覆盖，必要时邻窗 | 复验接缝，重拼整片 |
| 换配音，样本数相同 | 对比实际PCM，重算音频条件依赖相交窗口，含邻接上下文 | 保持其他已核验窗口，重建母轨与整片 |
| 改文本或配音后时长变化 | 先重建时间轨，再计算全部依赖差异；可能影响下游窗口、机位、动作排程，不能保证只重做一轮 | 展示受影响范围后执行，未变局部内容在验证可重新定位时才复用 |
| 只改字幕/编码/导出尺寸 | 若模型原生输入规格不变，不重采样 | 重新字幕/编码/封装检查 |
| 改脸部区域、模型、角色、运行时精度 | 相关模型窗口全部失效 | 重新检查与质量采用 |

时间变化默认提供“保持当前时长”和“按新配音重排”两个明确选项。保持时长不能偷偷加速音频、截断句子或修改母轨；超出当前时槽时应提示改稿或重排。重排以新音轨样本为准，不靠移动嘴型视频掩盖同步问题。

预览尾部仍使用原整期上下文。若后续文本/声音/动作改变了其上下文，原预览末尾窗口也必须失效。接缝检查失败时扩大到相邻窗口重新生成，不自动把全部整期重算作为唯一恢复方式。

## 服务与任务

建议独立服务`expert_preview`负责选轮/快照，`expert_regeneration`负责依赖比较与候选采用，复用既有任务账本、GPU队列、OwnedProcess及媒体检查。

建议接口（目前未实现）：

- `POST /projects/{id}/video-previews`：snapshotId、turnIds、复用策略；先返回计划及选中窗口，再以幂等clientToken执行。
- `POST /projects/{id}/video-rounds/{roundId}/regeneration-plans`：修改类型/候选配置；返回原始时间区间、需要重算/可复用窗口及原因。
- `POST /projects/{id}/video-regenerations`：planId、clientToken；显式运行冻结计划。
- `POST /projects/{id}/video-candidates/{candidateId}/adopt`：expectedProjectRevision；检查快照仍有效后原子采用。

状态：待生成→排队→生成→媒体检查→待审看→已采用，失败/取消独立保留。进度同时显示“第几轮”和真实模型窗口数。响应丢失按原任务ID续查，不能重复POST；取消只影响当前候选，不删除旧采用版。

## 实施顺序和验证

1. 两轮预览规划器：从冻结整期计划选取连续四话轮，扩展必需窗口及上下文，保持绝对位置/seed；默认plan不触发模型。验证跨窗、停顿、少于四话轮、机位变化及尾部上下文。
2. 接专家候选运行与样片审看；预览通过后整期复用已核验窗口，未变片段零额外采样。用实际提交计数证明复用，不能只验证cacheKey相同。
3. 同时长画面重做：主动新种子生成新候选，逐轮采用/回退，接缝不通过再扩大邻窗。验证未选区域无模型调用、失败不覆盖、并发改稿拒绝陈旧采用。
4. 配音/文本改动：复用现有voice_svc单元候选和时间轨，再做受影响范围计划；时长变化验证下游动作/机位/上下文失效。
5. 正式UI和API回归：完整话轮预览、采用后续算、某轮重做、断线续查、取消、旧版本回退、最终母轨样本和帧数一致。

代码基础：motion_schedule.py的整数样本动作计划、expert_motion.py的核心与上下文窗口、motion_segments.py的依赖复用提案、voice_svc.py的配音单元候选。现有motion_segments面向快速模型并包含Whisper上下文，不能直接当作专家ROI缓存契约；专家缓存需要独立绑定实际wav2vec/参考VAE/ROI/模型依赖。

优先完成第1～3项，先支持“不改时长的某轮画面重做”；随后扩展文本/配音造成的时间重排。当前运行中的冷模型稳定性复测不受此设计变更影响。
