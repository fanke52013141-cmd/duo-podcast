# 专家范围任务、候选采用与恢复

## 本次实现

- `expert-video/generate`：读取服务端持久化计划，校验工程与引擎身份，创建GPU队列任务。同一clientToken返回原任务；标识碰撞拒绝，不重复提交不明状态的外部任务。
- `expert.generate`：通过任务管理器调度专家适配器；重启恢复保留原任务ID、外部提示词ID及提交意图。不把新任务转发给旧整期或快速模式。
- 专家适配器从整期重建并校验原始计划，选择原绝对窗口。局部候选只改变对应采样身份。生成后单次裁切原母轨；审看媒体覆盖所有将更新的交接窗口。
- `candidates`：提供任务与候选状态；`adopt`要求四项人工审看声明、成功真实任务、当前工程依赖、登记媒体与文件哈希一致、版本修订号一致。
- `ExpertVersionStore`原子保存每次窗口选择、审看项、时间及恢复来源；失败或取消不写当前选择。恢复前重验历史候选文件与依赖。
- 页面接入范围检查、提交、视频播放、审看、采用、历史恢复、取消与新建重试任务。播放一支视频时暂停其他候选；媒体未加载或加载错误时禁用采用。

## 浏览器操作验收

2026-10-28本轮浏览器已可访问，之前禁用状态不再适用。通过CUA实际操作`tests/browser/expert.html`：

1. 默认四话轮范围检查。
2. 提交隔离模拟任务，查看候选；测试视频可读取，duration=8、readyState=4。
3. 四项勾选前采用按钮禁用；勾选后采用，版本变为1。
4. 切换单轮重做并选择第3话轮，提交、审看和采用，版本变为2。
5. 恢复版本1，产生版本3，刷新后仍选择首个候选。
6. 选择靠近结尾的话轮，显示不足四轮时使用完整剩余话轮的提示。
7. 390×844窄屏检查：无横向溢出（viewport390、document375），控件和视频可见；1280×900检查桌面布局。临时视口已恢复。

实测修复：选择器标签关联、提交后切换范围的禁用状态、测试媒体Range响应、视频加载失败时禁止采用。

浏览器使用生产组件与隔离的替代API，模拟状态保存在该测试页的独立localStorage。测试服务器拒绝全部未声明API请求；没有访问真实工程采用记录，没有模型调用。截图保存在`.review/expert-ux-accepted.png`。这证明交互链，不能证明真实模型质量或部署就绪。

## 部署边界与剩余工作

正式服务默认不装配专家执行器。显式服务器配置`DUOCAST_EXPERT_PREPARATION_ROOT`和`DUOCAST_EXPERT_ENGINE_FINGERPRINT`后才装配现有全画面专家适配器；使用服务器既有video_url与video_input。配置必须来自真实核验的引擎部署，不得用随意摘要冒充运行身份。单纯配置不能证明运行兼容与质量通过。

本次接通的是原专家全画面参考路径，**尚未把已采用的Sage＋ROI实验路径迁移为正式适配器**。页面会说明实际路径，不会把全画面路径称为区域提速版。当前没有启用真实模型执行，也未重新启动现有生产服务。

采用与恢复更新的是专家窗口选择账本；尚未把这份映射接入整期的复用续算与合成导出。现有整期导出页不会自动消费新选择。不能宣称预览已被整片复用，也不能宣称正式优化全部完成。

测试入口：在apps/web运行`npm run dev -- --config tests/browser/vite.config.ts`，访问`/tests/browser/expert.html`。媒体fixture需先用FFmpeg生成至仓库`.review/expert-ux-fixture.mp4`；这是色块媒体，不是角色效果样片。测试页不打包进生产入口。
