# 物品角色动作工作流：实施与验收总账

状态：实施中。起始代码 `105c7f64f52c8cb17faf19ef9f2113cf4319bf9d`。
本文件固定完整范围，不能因为某批测试通过而缩减最终交付目标。

## 1. 交付目标

新角色、新机位先制作并验收可复用动作资产；每期采用已有动作后合成配音、更新口型、规划同框和真实反打，再导出视频。保存原始素材、处理记录、检查证据、人工审看与不可变版本。静态素材不能冒充有动作；模拟测试不能证明真实模型效果。

已知实测边界：台灯和红绿灯8秒实验经过人工整理可行，但没有证明任意物品自动成功、长片自然度或逐句精确表演。物品活动结构与五官持续可见都必须检查。检测出脸不等于眼鼻嘴可用，正常眨眼不算物体遮挡。

## 3. 必须覆盖的验收场景

| ID | 场景 | 预期 |

| V03 | 只动背景或镜头 | 不误判物体动作 |

| V10 | 缺一个反打机位 | 页面和API均拦截该风格 |
| V11 | 连续提交同一请求 | 无重复推理 |
| V12 | 动作任务中重启 | 优先接原任务，不盲目重采样 |
| V13 | 已采用媒体变更 | 哈希异常，新生成停止，历史成片保留 |
| V14 | 旧工程/模板 | 原绑定和行为不被静默升级 |
| V15 | 同框/过肩共用配音 | 解码音轨一致 |

## 4. 产品和数据约束

- 动作包草稿、生成任务、自动检查、人工审看分开建模。自动报告不能冒充人工采用。
- 采用与版本冲突检查绑定，媒体/角色/机位/处理范围变化使对应结论失效，旧版本可读。
- 同框可用而反打缺失时，仅拦截反打；不静默替换为裁切或静态视频。
- 资产包只能通过已登记媒体引用访问内容，不接受执行任意运行时脚本或任意文件路径。
- 新工作流共享现有GPU排他队列；图像API/CPU工作可以受限并行。
- 提供方连接成功不代表额度充足或模型推理成功。余额未知不得显示为零或无限可用。
- 每期保持已有脚本、配音、样片确认逻辑；新动作包仅首次或内容变化时审看。
- 字幕、标题与包装文字处理不能以静态身体替换牺牲已经通过的动作。
- 模型权重、第三方环境、用户音色和成片保留本机；小型可再生测试数据进入测试工具。
