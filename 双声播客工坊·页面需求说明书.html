UI REQUIREMENT SPECIFICATION

双声播客工坊 · 本地工作台

面向 Windows 本地部署的双人 / 拟人物件播客视频生产控制台，编排"场景 → 角色 → 遮罩 → 音色 → 文案 → 试镜 → 成片"七步流程，底层调用本机 ComfyUI（127.0.0.1:8188）工作流，全部数据不出本机。

版本 v1.0载体：单页应用（SPA）运行：Windows 本地对应原型：index.html文档粒度：元素 / 功能 / 交互

0产品与范围

产品目标：让一位创作者无需手写 ComfyUI 节点连线，按七步向导即可产出 ≤10 分钟的双人（含拟人化动物 / 物件）对口型播客视频。

用户角色
单人创作者（同时是操作者），无多用户、无登录
运行形态
本地 Web 工作台，前端页面 + 本机 ComfyUI 推理服务；离线可用，文件不上云
页面总数
1 个主框架（顶栏 / 步骤轨 / 主区 / 底栏）+ 7 个步骤视图（页内切换，非跳转）
核心角色
A 主持人负责提问串联；B 被采访方人 / 动物 / 拟人物件（如会说话的砖头、墙）
本期范围
完整前端交互、流程编排、参数与状态管理；真实推理通过"本地接口预留"对接（见第 11 章）
全局配色语义：青蓝=角色 A，珊瑚粉=角色 B，焦糖=品牌与主操作，绿=成功 / 已连接，橙=警告 / 待处理，红=错误 / 删除。颜色不作为唯一信息载体，始终配合文字标签。

3页面② · 角色

页面目标：确定 A 主持人与 B 被采访方（人 / 动物 / 拟人物件），通过 G1 合格门后把两位合成进场景。关键规则：拟人物件必须在出图阶段就带有清晰的嘴和眼，否则无法驱动口型。
角色 A形象类型选择→上传正面半身→角色 B必须带嘴/眼→G1 合格门→合成进场景

4页面③ · 遮罩

页面目标：在合成图上分别涂抹 A、B 的"音频驱动动态区"。遮罩把口型 / 头肩动作局部化到对应角色，是"谁说话谁动"的几何依据。原则：只框脸 + 嘴，宁小勿大；物件 B 尤其不能涂满整个表面。

5页面④ · 音色

页面目标：为 A、B 各指定一条本地参考音频，由本地 IndexTTS-2.5 做零样本音色克隆，并分别设定情绪与语速。模型不支持凭空"设计"嗓音，换音色=换参考音频。

P4-A音色 A主持人

元素类型默认 / 取值功能与交互
参考音频槽上传槽 + 文件选择空态"WAV/MP3 · 建议 10–20 秒、无背景噪"接受 audio/*，仅本地读取；载入后显示文件名与"用于本地零样本克隆"；可替换；建议时长 3–30 秒，超出提示裁剪
情绪下拉选择平静（默认）/ 开心 / 好奇 / 严肃 / 惊讶选择写入该角色情绪参数；与音色解耦，可独立于参考音
语速下拉选择0.9× / 1.0×（默认）/ 1.1×控制该角色整体语速

P4-B音色 B拟人物件

元素类型默认 / 取值功能与交互
参考音频槽上传槽 + 文件选择空态，建议"有性格的嗓音：老成 / 俏皮 / 冷淡"同 A；建议 A、B 音色一高一低、一快一慢以保证区分度
情绪下拉选择俏皮（默认）/ 平静 / 委屈 / 沧桑 / 激动同 A 逻辑
生成试听句次级按钮—用一句固定示例文本 + 当前参考音 / 情绪在本地合成并播放；真实环境返回音频并内置播放器，原型为提示
完成条件：A、B 各载入一条参考音即标记完成。接口：试听与正式合成调用本地 IndexTTS 节点，入参=文本 + 参考音 + 情绪（类别 / 权重）+ 语速；详见第 11 章。

6页面⑤ · 分角文案与双轨对齐

页面目标：逐句编写标注说话人的脚本，实时估算时长，并把 A、B 拼成两条等长音轨——一方说话时另一方同时段补静音，这是"谁说话谁动嘴、对方不抢话"的关键。

P5-1分角色脚本编辑器

元素类型默认 / 取值功能与交互
脚本行行组件：角色键 + 文本域 + 删除预置 3 行 A/B/A 示例对话角色键底色区分 A/B，点击在 A↔B 间切换；文本域随输入自动增高、实时刷新统计；删除键移除该行（至少保留 1 行，删空时自动补一空行）
+ A 句 / + B 句次级按钮—在末尾插入对应角色空行并聚焦
按热点起草次级按钮—用"热点 + 拟人物件第三方视角"模板填充一组示例台词（覆盖前二次确认），用户可再改；真实环境接 LLM 按热点生成

P5-2统计与双轨时间轴

元素类型计算 / 默认功能与交互
总字数数值所有行去空白后字符数，实时只读
A 句 / B 句数值 ×2按角色计数只读
预计成片时长数值（分:秒）按中文 4.2 字/秒逐句累加，每句额外 +0.25s 停顿只读，随编辑实时更新；超过 10:00 转橙提示"成片将超过 10 分钟"
生成对齐双轨主按钮—空脚本时禁用并提示；点击后按下方算法渲染双轨时间轴，状态变双轨已对齐 · 总时长 mm:ss，标记本步完成
A 轨 / B 轨双时间轴 lane两条等高轨道 + 底部 5 等分时间刻度说话片段为彩色块，左右位置=开始时间占比、宽度=时长占比，块内标字数、悬停显示时长；同一时刻另一条轨道对应位置留空（即静音）；两轨总时长强制相等
时长与对齐算法（前端预算，最终以 TTS 实际时长为准回填）：单句时长 dur=max(1.2, 字数/4.2)+0.25s；按行顺序首尾相接得全局时间轴；A 句只画在 A 轨、B 句只画在 B 轨，从而天然互补；提交时把每句文本送对应音色 TTS，再按全局时间轴用静音把两条音轨补齐到同一总时长。

7页面⑥ · 快速试镜

页面目标：用极短样片低成本验证口型与角色，通过后才投入长片渲染；不通过就回到第 2/3 步换角色或重涂遮罩，工作流模板保持不动。

回第二步换角色文字按钮—直接跳转页面②，保留已填内容

P6-R样片预览与验收

预览区16:9 播放器空态提示生成后播放本地视频文件；显示规格与种子
验收项 ×4勾选清单①嘴型跟音 ②静音方不抢话 ③脸/物体不变形背景不扭曲 ④风格统一逐项勾选，勾中变绿；四项全勾才标记本步通过并解锁长片；任一不勾保留"待整改"，按页面提示回第 3 步收遮罩或第 2 步换图
迭代成本控制：换角色只替换第 2 步图片与第 3 步遮罩，脚本、音色、参数模板不变，单次小样仅几十秒。

8页面⑦ · 分段渲染与导出

页面目标：把整片按对话切成 15–30 秒分段逐段渲染（段间 25 帧重叠保证连贯、固定底图与种子防漂移），完成后拼接、RIFE 补帧并导出 ≤10 分钟成片。

9全局交互规则与状态机

9.1 步骤完成条件

步骤完成判定未完成时的表现
① 场景存在场景底图（生成或上传）下游合成无背景，用站位占位图
② 角色G1 三项全勾且点击"合成"成功合成按钮禁用；遮罩页无合成底图
③ 遮罩A、B 遮罩像素均超阈值（单人模式可跳过）驱动时无法区分两位角色动态区
④ 音色A、B 均已载入参考音频无法生成对应角色语音
⑤ 文案≥1 句台词且已"生成对齐双轨"渲染队列为空
⑥ 试镜四项验收全部勾选不建议进入长片（仅提示，不硬锁）
⑦ 成片全部分段状态=已完成"拼接并导出"禁用

9.2 全局交互约定

  • 导航：步骤可自由前后跳转、允许前跳；点"下一步"才把当前步写入已完成；侧栏用编号 / 绿勾 / 高亮区分未开始、完成、当前。
  • 文件读取：所有图片、音频经浏览器 FileReader 在本机转 DataURL / ObjectURL 预览与暂存，不发起上传；刷新页面后本地暂存清空（真实版改为从本地工作目录读取）。
  • 遮罩绘制：底图层只读 + 离屏遮罩层可绘；A/B/橡皮三态互斥；抬笔时按颜色像素阈值更新"A/B 已涂"；坐标随画布显示尺寸等比换算，兼容触摸。
  • 双轨对齐：按 4.2 字/秒前端预估并互补静音；真实 TTS 产出后以实际音频时长回填、重新拉平两条轨道。
  • 试镜回退路径：嘴不动 / 乱动→回第 3 步收紧或重涂遮罩、核对音轨绑定；画面崩→回第 2 步换更标准的"正脸带嘴"角色图。
  • 渲染队列：串行状态机 待渲染→渲染中→已完成；单段失败显示"失败 / 重试"，不影响已完成段，可从失败段续跑。
  • 反馈与异常：操作结果统一走 Toast；空态给出下一步行动文案而非空白；引擎断开时所有"生成 / 渲染"按钮禁用并说明如何启动本地服务。

12非功能需求与本期边界

12.1 非功能需求

本地 / 隐私默认仅访问 127.0.0.1；图片音频不出本机；无账号、无埋点上云；界面常驻"全本地运行"标识

性能纯前端操作（编辑 / 涂抹 / 统计）即时响应；耗时任务（TTS / 渲染）全部异步、可看到进度、不阻塞界面
